## 1. Cyxd Daemon Architecture

The `cyxd` daemon provides the local execution environment for the CyExchange protocol. It acts as the physical membrane separating external untrusted networks from local 101 actuator execution.

*   **Initialization (`cyxd init`):** Generates local Ed25519 `NodeCard` parameters securely.
*   **Routing (`cyxd route`):** Validates the `required_state` against the incoming envelope. 
*   **Inbox Serving (`cyxd serve`):** Implements the durable state machine described in the CyExchange protocol, ensuring atomic transitions from `RECEIVED` to `EVALUATING`.

## 2. Bleed-Over Membrane Enforcement

The daemon explicitly prevents $\beta$-boundary bleed-over by enforcing the Permit Doctrine:

1.  If an Envelope claims `101` (Actuator Effect), `cyxd` immediately isolates the payload.
2.  The `permit.Verify()` routine is executed against the `SovereignApplyPermit` attached to the envelope.
3.  If the verification fails for *any* reason (expired, invalid signature, mismatched hash), the daemon terminates the transition, records `REJECTED`, and dispatches an `EvaluationReceipt` indicating failure.
4.  The untrusted payload is never deserialized into executable system memory.

This ensures that theoretical assertions generated by an AI (`010`) cannot autonomously trigger a deployment or mutation without the explicit cryptographic backing of the Sovereign operator.
